# 0004 许可证：Apache-2.0

- 状态：已采纳
- 日期：2026-10-29

## 背景

仓库此前**没有 LICENSE**，按默认规则等于「保留全部权利」。这带来三个问题：

1. 团队派生项目 `batter-campus` 已经 clone 了 0.9.0 做闭源商业化改造，法律上处于无授权使用状态；
2. 对外，别人只能看、不能合法复用，说「开源」名不副实；
3. 各类开源平台与包管理器的元数据也无法识别本项目的授权。

需要同时满足：允许他人在明确条件下（含商业用途）复用、不放弃署名、不授权品牌。

## 决策

采用 **Apache License 2.0**，许可证全文见仓库根目录 `LICENSE`，署名与第三方说明见 `NOTICE`。

## 理由

- **明确授予专利许可**（第 3 条）：这类项目会踩到界面/交互与压缩、扫码等实现，MIT 无专利条款，风险更高；
- **要求保留版权与 NOTICE**（第 4 条）：派生项目必须带上「基于 erke++」的溯源，避免被包装成原创；
- **不授权商标与产品名**（第 6 条）：`二课++` 这个名字与图标仍归作者，派生项目必须换名换图标；
- **商业用途不设限**：与「主线开源、派生项目自己商业化」的定位一致，不做许可证层面的壁垒；
- 生态兼容：Android 侧依赖（AndroidX、Compose、OkHttp、Coil、kotlinx）同为 Apache-2.0，不产生额外义务。

## 被排除的选项

| 选项 | 否决原因 |
| --- | --- |
| MIT | 无专利授权、无 NOTICE 义务，溯源更容易被抹掉 |
| AGPL-3.0 | 会强制派生项目开源，与团队「闭源商业化」直接冲突，等于逼他们违规 |
| 保留全部权利（现状） | 「开源」名不副实；派生项目的使用始终悬空，反而更容易出纠纷 |
| 非商业许可（如 PolyForm Noncommercial） | 不是 OSI 认可的开源许可；且团队商业化要靠单独谈判，成本高于收益 |
| 双许可（Apache + 商业） | 只有在需要「闭源且不署名」时才值得，目前没这个诉求 |

## 后果

- 任何人都可以闭源商用，但**必须**：保留 LICENSE/NOTICE、标注修改、不得使用本项目名称与图标、不得暗示官方背书；
- 团队派生项目因此**不需要**单独的代码授权，仍然**需要**单独处理：包名、签名、品牌、隐私声明与合规口径（见交接文档）；
- 仓库所有者不承诺技术支持与更新；不承担使用者调用官方接口产生的责任（第 7、8 条）。

## 如果要收紧

改 LICENSE 即可，但对**已经按 Apache-2.0 获得的版本**（含 0.9.0）不具追溯力。若将来要禁止商业使用，
应同时：替换 LICENSE、在 README 与发版说明中注明生效版本、对派生项目单独发函。
