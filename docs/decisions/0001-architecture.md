# 0001 客户端形态：壳优先的混合方案

- 状态：已采纳
- 日期：2026-10-21

## 背景

官方站点 `https://win.9xueqi.com` 是 Vue2 + Vant 的移动端 H5，功能完整但交互与视觉被用户认为「丑且难用」。
既有第三方原生客户端（位于工作区外的旧项目）曾完整重写，最终因接口逐个硬啃、写操作未验证、文档失真而难以维护。

## 选项

1. **纯 WebView 壳**：兼容性最好，但界面与官方完全一致，不解决初衷。
2. **纯原生**：界面最好，但 195 个接口需逐个验证，站点改版即失效。
3. **混合（壳 + 逐页原生）**：长尾页面交给壳，高频页面原生；任一原生页出问题可单独回退。

## 决策

采用方案 3，且第一阶段（v0.1.0）只做壳：

- 壳负责：登录、回调、文件选择、下载、外部链接、错误页、Cookie/DOM Storage 持久化。
- 原生负责：v0.2.0 首页与登录，v0.3.0 活动列表/详情，v0.4.0 二课成绩。
- 壳与原生共用同一 JWT：壳内登录后从 WebView 的 `localStorage` 取出 token，交由原生层保管使用；不在应用内保存学号密码。

## 后果

- 优点：v0.1 即可全功能使用；站点更新自动生效；原生页可独立回退。
- 代价：壳阶段的界面观感等同官方；原生页需要与站点接口保持同步，需维护接口验证清单。
- 约束：原生页面必须带「回退到 WebView」开关，不得出现无法使用的死页面。
