# 组织（v0.9.0）

官方把「组织」摊在三个页面里，学生用得上的是三个入口：

| 入口 | 官方页面 | 本应用 |
| --- | --- | --- |
| 我参加过哪些组织 | `#/myOrganization` | 「我的」→ 我的组织 |
| 全校有哪些组织 | `#/service/organize` | 「更多」→ 所有组织 |
| 某一个组织是谁 | `#/orgDetail/<id>` | 组织详情页；扫组织码也落在这里 |

接口与字段见 [官方站点接口实测记录](../api/win-9xueqi-api.md) 的「组织」一节。

## 底部导航与「更多」

底部从三格变四格：发现 / 我的 / 更多 / 设置。**「我的组织」不进「更多」**——它属于「我」，
和诚信值、我的附件同级。放「更多」里的是公共入口：所有组织、加入组织、修改个人资料、官方页面。

以后每做一个官方页面就先算清楚归属：跟人有关系的进「我的」，跟内容有关系的进「发现」或
「更多」；只有真的成为主要用法时才给它一个底部 tab，否则底部会一直长。

## 我的组织

三个列表 × 三种审核状态，就是官方那九个格子，参数一字不差：

```
kind   = 我加入的（my-list）/ 我创建的（my-create-list）/ 我退出的（my-quit-list）
status = 待审核(1) / 已通过(2) / 已驳回(3)
```

- 默认停在「我加入的 + 已通过」：这是这个页面最常被打开的理由。
- 每条显示：头像、名称、身份标签（管理员 / 负责人）、成员数、活跃值、申请日期、
  审核状态；被驳回的在下面补一行驳回理由。
- 组织自身的生命周期（已注册、年审中、已注销…）与审核状态是两回事，各占一行，不混在一起。
- 服务端已按 `status` 过滤，客户端不再二次筛；列表项缺 `status` 字段时按当前筛选标签显示。
- 分页按 `total` 收尾（响应里没有 `lastPage`）。

### 翻页踩过的两个坑

1. 触发加载的 `LaunchedEffect` 的 key 里**不能**放 `loadingMore`：它在效果自己发起的请求里被改写，
   key 一变组合就取消这次请求，然后重进效果再发一次——列表卡在「一直转圈、永远没有第二页」。
   请求用 `rememberCoroutineScope()` 发出去，key 只放 `nearEnd / items.size / lastPage`。
2. `catch (Throwable)` 会把 `CancellationException` 也吃下去，界面上看起来是「加载失败」，
   实际是正常取消。取消要原样抛出去，只处理真正的失败。

## 所有组织

对应官方 `#/service/organize`，版式照发现页：药丸搜索框 + 一行分类 chip + 一行排序 chip +
双列卡片（**1:1 图位，logo 铺满**：`ContentScale.Crop`；没有 logo 的组织用主题容器色铺满 + 首字），
卡片右上角挂「申请加入 / 已加入」。

数据走 `organization/page/organization/list`，不是「我的组织」那族接口。

### 三个 tab

| tab | 接口 | 卡片角标 |
| --- | --- | --- |
| 未申请 | `page/organization/list` | 申请加入 / 已加入 |
| 已申请 | `my-apply-list1` | 待审核 / 已通过 / 已驳回 |
| 已加入 | `my-list`（按分类） | 已加入 |

判重：`my-apply-list1` 里通过之后记录仍在，所以同一个组织会同时出现在「已申请」和
「已加入」。这不是 bug，官方也是这样；「已申请」用 `applyStatus` 显示结果，
「已加入」只用来看我进了哪些。

### 分类与排序

- **分类**来自字典 `dict/organization/choice-sort` 的 `filterArray`：
  全部(0) / 学生会组织(3) / 社团与协会(2) / 志愿组织(5) / 其他(19)。实测总数
  140 / 37 / 99 / 0 / 1。
- **排序**是「最新(0) / 最热(1)」。字典里的 `sortArray` 写着「1 最热、2 最活跃」，
  那是别的页面用的；这一页官方下拉写死最新/最热，发给接口的值是 0/1（`popClick`）。
  照字典发会把最热发成 0，等于永远停在最新。
- 官方页顶部的「未申请 / 已申请 / 已加入」三个 tab 没有做：前者是本页，后两者和
  「我的组织」重复，做了会让人两处维护同一个列表。

### 搜索为什么是本地做的

服务端不认 `search`：传「协会」「人工智能」和传空字符串，总数都是 140、列表也一样。
照官方那样把参数发过去只会得到一个假搜索框。所以输入后先把当前分类的整份目录
分页拉完（140 个，7 页），再按名称/简介匹配，结果按「分类|排序」缓存，切回来不再拉。

### 预加载

和发现页共用同一个「预加载下一页」开关与阈值（`shouldLoadMore`）：开着时剩 8 条就取
下一页并预取后面 12 张图；关掉只在剩 2 条时才取、也不预取。列表底部到底时显示
「加载更多」按钮兜底。

## 组织详情

- 头部：头像、名称、性质 + 分类（`natureName` · `categoryName`）、成员数 / 活跃值 / 组织状态
  三格，挂靠单位、会长、指导老师各一行。
- 简介：`introduce`。
- 主办活动：`organization/activity-list` 前 10 条，点进去是活动详情。
- 底部动作：能申请就给「申请加入」，否则给一句状态（已提交申请，等待审核 / 已加入 /
  申请被驳回 / 不接受自己申请 / 暂未开放加入）。

### 申请加入

- 理由必填（官方空着会弹「请输入申请信息」），多行输入。
- 确认框里照搬官方的提醒：**加入组织后不能自己退出**。
- 已经在审核中的组织不给按钮——`applyStatus=1` 时再点一次就是重复提交。
- 被驳回（`applyStatus=3`）可以「重新申请」。

## 组织码

官方生成的码是明文 `qutuo://joinOrganization?id=<组织id>`，扫码后官方会补一段
`?yiban=yiban_scan_result`（第二个问号）。包里的 `Encrypt`/`Decrypt` 是恒等函数，
所以客户端不需要解密，按 `?yiban=` 截断再取 `id` 就行，解析在 `ScanRouter.organizationId`。

两个扫码入口分工：

| 入口 | 认什么 | 扫到别的 |
| --- | --- | --- |
| 发现页「扫一扫」 | 签到码、活动分享码、组织码 | 提示「这不是活动签到码」 |
| 更多 →「加入组织」 | 只认组织码 | 提示「这不是组织码」，**不会把签到码签了** |

「加入组织」里故意不解析签到：两个页面长得一样，站错地方把签到签掉，比多扫一次麻烦得多。

## 没有做的

- **退出组织**：官方有 `organization/quit/user-apply`，走申请-审核流程；这次没接，
  「我退出的」只读。
- **组织成员 / 公告 / 相册 / 荣誉**：详情接口一次给全（`memberList` 实测 793 条），
  但学生端不常翻，先不铺。
- **换届、年审、评优流程**：属于管理员（`identity` 2/3）的操作，学生端用不到。
