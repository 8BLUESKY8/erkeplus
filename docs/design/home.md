# 发现页设计（v0.2 概念版）

- 状态：概念版已实现并在真机验证，待最终确认
- 日期：2026-10-21

## 目标

首屏解决"有什么我能报的活动"。不做仪表盘、不做日历、不做个人信息。

## 结构

```
发现                                   我的
[ 搜索活动名称                    ]
[报名中] [待开始] [进行中] [全部]
[全部] [思想政治引领] [实践能力培养] …   最新
┌──────────┐  ┌──────────┐
│ 封面 4:3  │  │ 封面 4:3  │   角标：推荐 / 报名中
└──────────┘  └──────────┘
 标题两行        标题两行
 5学时·分类      5学时·分类
 1363人报名·校团委  …
```

## 数据

| 元素 | 来源 |
| --- | --- |
| 列表 | `GET /page/activity/list`（11 个必填参数） |
| 分类 | `GET /dict/activity/choice-sort?moduleId=1` → `filterArray` |
| 状态 | `activityStatus`：5 报名中、6 待开始、7 进行中、8 已结束 |

## 交互约定

- 搜索：首屏常驻输入框，400ms 防抖，走服务端 `search` 参数。
- 筛选：状态与分类单选，切换后回到顶部并重新拉第一页。
- 分页：滚动接近末尾自动加载下一页，页大小 20。
- 点击卡片：跳官方网页详情（`#/ActivityShow/{id}`），v0.3 再换原生。

## 已知取舍

- 不做日历选日：与"发现可参与"的目标冲突。
- 不做列表内报名：写操作未验证，一律先进详情。
- 分类行横向滚动，一屏放不下全部 7 项。

## 实现要点

- 请求带代号（generation）：筛选切换后丢弃在途旧请求，避免新旧数据混排导致 id 重复崩溃。
- 列表回顶部用 `requestScrollToItem`，不使用挂起版 `scrollToItem`（列表未布局时会一直挂起）。
