# 主页与导航设计（v0.2）

- 状态：概念版已实现，真机验证通过
- 日期：2026-10-21

## 整体结构

```
┌──────────────────────────────┐
│ [ 搜索活动名称            ]   │  顶部只有搜索框，不放大标题
│ [报名中][待开始][进行中][全部] 最新│
│ [分类…]（可在设置里关闭）        │
│ ┌────────┐  ┌────────┐       │
│ │ 封面    │  │ 封面    │       │  双列卡片，角标：推荐 / 状态
│ └────────┘  └────────┘       │
│  标题两行      标题两行         │
│  5学时·分类    5学时·分类       │
│  人数·组织     人数·组织        │
├──────────────────────────────┤
│   发现        我的        设置   │  底部导航
└──────────────────────────────┘
```

## 底部导航

| 页 | 内容 |
| --- | --- |
| 发现 | 活动流（本节） |
| 我的 | 个人信息、学分、学时、进入官方网页 |
| 设置 | 分区卡片：发现页 / 活动卡片 / 内容屏蔽 / 账号 / 关于 |

三页放在一个横向分页容器里，`PageSize.Fill`，并且全部常驻（`beyondViewportPageCount` = 页数）。
好处有两个：左右滑动可以直接换页；换页不重建界面，发现页的滚动位置、已加载数据都保留。

- 点底部导航：立即高亮，分页容器动画滑过去。
- 左右滑动：滑动落定后才更新当前页，避免拖动过程中来回横跳。
- 双击底部「发现」：重新拉取列表（400ms 内的两次点击算双击）。
- 重新进入发现页：默认保持位置，可在设置里改成回到顶部或重新加载。

## 设置页结构

一条滚动列表，每组相关项放在同一块圆角底板上：

| 分区 | 内容 |
| --- | --- |
| 发现页 | 显示分类筛选条、卡片显示分类标签、预加载下一页、分类入口 chips |
| 活动卡片 | 显示封面、显示学时、显示报名人数、显示主办组织、卡片附加文字、标题行数 |
| 内容屏蔽 | 一行概览（关键词 N 条 · 正则 M 条 · 无效 K 条），点击进入独立页编辑 |
| 账号 | 姓名 · 学号、退出登录 |
| 关于 | 开发者模式、免责声明与隐私说明、版本号 |

页面底部有「恢复默认设置」，二次确认后重置显示与筛选偏好，不动登录态。

偏好只有一份数据：`AppPreferences` 的每个字段本身就是 Compose 状态，界面直接读写，改完立即生效并落盘。

## 分类可配置（设置页）

在 `设置 → 发现页 → 显示哪些分类入口` 中：

1. **显示分类筛选条**：关闭后发现页不显示任何分类 chip，只用状态与搜索筛选。
2. **卡片显示分类标签**：关闭后卡片只显示「5学时」，不显示分类名。
3. **显示哪些分类入口**：勾选具体分类，默认勾选「思想政治引领 / 实践能力培养 / 综合素质拓展」，`全部` 始终保留。

配置持久化在本地偏好中，重启后保持。

## 数据

| 元素 | 来源 |
| --- | --- |
| 列表 | `GET /page/activity/list`（11 个必填参数） |
| 分类 | `GET /dict/activity/choice-sort?moduleId=1` → `filterArray` |
| 状态 | `activityStatus` 不能直接当阶段：1、3 是未审核（学生端不可报名），5 才是报名中；阶段由四个时间点算（见 [术语库](../../GLOSSARY.md)） |

筛选标签发出的 `status`：

| 标签 | status | 说明 |
| --- | --- | --- |
| 报名中 | `5` | 学生端唯一可报名的编号 |
| 待开始 | `6` | 报名已截止、活动未开始 |
| 进行中 | `7` | |
| 全部 | `4,5,6,7,8` | 4 恒为 0 条（服务端把待报名的活动摘掉了），8 是已结束 |

2026-10-23 实测：`4,5,6,7,8` 共 178 条，其中 `hours <= 0` 的 0 条。
不带 1、3 是有意的——那 46 条是未审核活动（官方页面底部写「未审核」，学时也是 0），
它们只在显式按状态过滤时才返回。旧版本存的 `5`、`4,5,6,7`，以及 0.8.2 早期版本误存的
`1,3,5`、`1,3,4,5,6,7,8`，在读出来时都会被换成上面的集合。

## 交互约定

- 搜索：常驻输入框，400ms 防抖。**本地匹配**，不用服务端 `search`（该字段只影响 `total`，见 API 文档）：
  输入关键词后先把列表拉到最后一页（最多 40 页，实测全校 224 条约 12 页），
  再在本地按标题 / 主办单位 / 分类名匹配，多个词空格分隔需全部命中。
  扫描中显示「正在搜索全部活动… 已扫描/总数」，结束后显示「在 N 条活动里匹配到 M 条」。
- 筛选：状态、分类单选；切换后回到顶部并重拉第一页。
- 分页：滚动接近末尾自动加载，页大小 20；结果按 id 去重。
- 封面：按卡片实际显示宽度解码，宽度上限 720 像素；新到的一批先预取进内存缓存，滚动时不再临时解码。
- 点击卡片：跳官方网页详情（`#/ActivityShow/{id}`），后续版本再换原生。

## 已知取舍

- 不做日历选日：与"发现可参与"的目标冲突。
- 不做列表内报名：写操作未验证，一律先进详情。
- 分类 chip 仍可能横向溢出：由用户勾选入口数量控制，属预期行为。

## 返回与过渡（v0.5.2）

- 二级页面统一用 `SecondaryPage` 外壳：不透明背景 + 180ms 入场位移淡入。
- 返回走预测性返回（Predictive Back）：`PredictiveBackHandler` 拿到手势进度 0..1，直接映射成位移、透明度与 0.96 缩放；中途松手弹回且不导航，提交时补 120ms 收尾再导航。
- 三键导航与 Android 12 及以下拿不到进度事件，退化为一次 120ms 收尾动画。
- 根页面（发现页）不再拦截返回，由系统直接退出应用；`AndroidManifest.xml` 打开 `enableOnBackInvokedCallback`。



## 附件与预览（v0.5.0）

附件统一落在公共下载目录 `Download/ErkePlus/`。

| 系统 | 写入方式 | 权限 |
| --- | --- | --- |
| Android 10+ | MediaStore Downloads（`IS_PENDING` 两段式写入） | 无 |
| Android 9- | 直接写文件 + MediaScanner | `WRITE_EXTERNAL_STORAGE`（声明限制 `maxSdkVersion=28`） |

- 下载队列是进程级的：切页面、切标签不中断，只有杀进程才停。进度用 `StateFlow` 暴露。
- 大于 5 MB 先提示网络环境。
- 「我的 → 附件」：进行中的任务（进度、取消、失败重试）+ 已下载文件（缩略图、打开、分享、删除）
- 视图可切换：分条列表（默认）/ 双列卡片，选择记在本地偏好里
- 删除有二次确认，可选放进回收站：Android 11+ 用系统 `IS_TRASHED`（30 天自动清理），Android 10 及以下用自建 `Download/ErkePlus/.trash/`；两种都支持还原与彻底删除。
- 图片预览：全屏、双指缩放、双击放大、左右滑动、页码；只读本地文件，不联网。
- 非图片文件交给系统应用打开；压缩包暂时只提示不支持。
- 所有二级页面都是全屏覆盖层，不保留底部标签栏：活动详情、查看作业、我的活动、附件、预览、屏蔽规则。
- 覆盖层**按依赖顺序写在同一个组合里**（先写的在下、后写的在上），因为这几层会叠加：
  我的活动 / 附件 / 我的组织 / 所有组织 / 加入组织扫码 → 组织详情 → 活动详情 → 作业 →
  签到扫码 → 图片预览 → 网页。从组织详情点进活动时**不清** `orgDetailTarget`，
  活动详情压在组织页之上，返回时组织页原样还在；写错顺序的代价就是「返回直接退回首页」。
- 覆盖层的正文统一**等入场动画（180ms）结束后再组合**：页面一挂载就联网、解析 JSON、铺列表，
  会和动画抢同一帧，表现就是「点进去卡一下」。这是 `SecondaryPage` 的职责，
  新页面不用自己处理。动画期间只显示一个转圈，正文再淡入 160ms、转圈同步淡出，
  不会「硬蹦出来」，中间也不留空白帧。



## 活动详情（v0.4.0）

点卡片打开原生详情，作为一个**覆盖层**压在分页容器之上：返回时列表还在、位置不丢。

```
┌──────────────────────────────┐
│ [←]  封面 16:9 + 压暗渐变      │
│ （进行中）（分类名，单行省略）  │
│ 标题（headlineSmall，粗）      │
│ 组织名（带 22dp 头像）         │
│ ┌── 8 ──┬─ 19/33 ─┬─ 10-29 ─┐ │  学时 / 已报名 / 结束时间
│ ┌ 报名时间 / 活动时间 ──────┐ │
│ │ 活动地点 / 联系方式 / 管理员│ │
│ ┌ 参与限制（有值才显示）─────┐ │
│ 活动介绍（纯文本直出，HTML 才走 WebView）
│ └────────── 底部按钮 ────────┘ │  「去官方页面报名」
└──────────────────────────────┘
```

- 卡片统一 18dp 圆角 + 1dp 描边，不使用大面积灰底，深浅色主题同一套结构。
- 学时、报名人数、结束时间做成三个大数字，先给结论再看细节。
- 介绍字段多数是纯文本，直出 `Text`；只有含标签时才用只读 WebView，并按主题色注入文字颜色。
- 不写任何数据：报名、取消仍跳到官方页面（写操作未验证）。
- 调试：`adb shell am start -n <包名>/gitee.leolin_me.erkepp.MainActivity --el detail_id <活动id>` 直接开详情。
