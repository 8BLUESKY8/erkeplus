# 主页与导航设计（v0.2）

- 状态：概念版已实现，真机验证通过
- 日期：2026-10-21

## 整体结构

```
┌──────────────────────────────┐
│ [ 搜索活动名称            ]   │  顶部只有搜索框，不放大标题
│ [报名中][待开始][进行中][全部] 最新│
│ [分类…]（可在设置里关闭）        │
│ ┌────────┐  ┌────────┐       │
│ │ 封面    │  │ 封面    │       │  双列卡片，角标：推荐 / 状态
│ └────────┘  └────────┘       │
│  标题两行      标题两行         │
│  5学时·分类    5学时·分类       │
│  人数·组织     人数·组织        │
├──────────────────────────────┤
│   发现        我的        设置   │  底部导航
└──────────────────────────────┘
```

## 底部导航

| 页 | 内容 |
| --- | --- |
| 发现 | 活动流（本节） |
| 我的 | 个人信息、学分、学时、进入官方网页 |
| 设置 | 分区卡片：发现页 / 活动卡片 / 内容屏蔽 / 账号 / 关于 |

三页放在一个横向分页容器里，`PageSize.Fill`，并且全部常驻（`beyondViewportPageCount` = 页数）。
好处有两个：左右滑动可以直接换页；换页不重建界面，发现页的滚动位置、已加载数据都保留。

- 点底部导航：立即高亮，分页容器动画滑过去。
- 左右滑动：滑动落定后才更新当前页，避免拖动过程中来回横跳。
- 双击底部「发现」：重新拉取列表（400ms 内的两次点击算双击）。
- 重新进入发现页：默认保持位置，可在设置里改成回到顶部或重新加载。

## 设置页结构

一条滚动列表，每组相关项放在同一块圆角底板上：

| 分区 | 内容 |
| --- | --- |
| 发现页 | 显示分类筛选条、卡片显示分类标签、预加载下一页、分类入口 chips |
| 活动卡片 | 显示封面、显示学时、显示报名人数、显示主办组织、卡片附加文字、标题行数 |
| 内容屏蔽 | 一行概览（关键词 N 条 · 正则 M 条 · 无效 K 条），点击进入独立页编辑 |
| 账号 | 姓名 · 学号、退出登录 |
| 关于 | 开发者模式、免责声明与隐私说明、版本号 |

页面底部有「恢复默认设置」，二次确认后重置显示与筛选偏好，不动登录态。

偏好只有一份数据：`AppPreferences` 的每个字段本身就是 Compose 状态，界面直接读写，改完立即生效并落盘。

## 分类可配置（设置页）

在 `设置 → 发现页 → 显示哪些分类入口` 中：

1. **显示分类筛选条**：关闭后发现页不显示任何分类 chip，只用状态与搜索筛选。
2. **卡片显示分类标签**：关闭后卡片只显示「5学时」，不显示分类名。
3. **显示哪些分类入口**：勾选具体分类，默认勾选「思想政治引领 / 实践能力培养 / 综合素质拓展」，`全部` 始终保留。

配置持久化在本地偏好中，重启后保持。

## 数据

| 元素 | 来源 |
| --- | --- |
| 列表 | `GET /page/activity/list`（11 个必填参数） |
| 分类 | `GET /dict/activity/choice-sort?moduleId=1` → `filterArray` |
| 状态 | `activityStatus`：5 报名中、6 待开始、7 进行中、8 已结束 |

## 交互约定

- 搜索：常驻输入框，400ms 防抖，走服务端 `search` 参数。
- 筛选：状态、分类单选；切换后回到顶部并重拉第一页。
- 分页：滚动接近末尾自动加载，页大小 20；结果按 id 去重。
- 封面：按卡片实际显示宽度解码，宽度上限 720 像素；新到的一批先预取进内存缓存，滚动时不再临时解码。
- 点击卡片：跳官方网页详情（`#/ActivityShow/{id}`），后续版本再换原生。

## 已知取舍

- 不做日历选日：与"发现可参与"的目标冲突。
- 不做列表内报名：写操作未验证，一律先进详情。
- 分类 chip 仍可能横向溢出：由用户勾选入口数量控制，属预期行为。
