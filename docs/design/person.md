# 人物主页

对应官方 `#/userShows/<id>`。只读为主，唯一的写操作是关注 / 取关。

## 入口

- 排行榜：前三名（领奖台）与榜内每一行都可点，用 `RankEntry.userId`；自己那一行也能点（进自己主页，不显示关注按钮）
- 组织详情：负责人每一行可点，用 `member-list` 的成员 `id`
- 组织成员列表页还没做，做出来同样接这里
- 调试入口：`am start ... --es probe user_page --el user_id 1908337`
- 层叠顺序：排行榜 → 组织详情 → 人物主页 → 参加的活动 → 活动详情（后出现的压在上面，
  `MainActivity` 里按这个顺序写，写错就会出现「返回后回到别的页」）

## 版式

```
┌ 返回  姓名 ──────────────────────┐
│ (头像 72dp)  姓名 [男]            │
│              学院 · 专业           │
├ 概况 ───────────────────────────┤
│ 参加活动   共 N 次                │
│ 加入组织   共 N 个                │
│ 广场动态   共 N 个                │
├ 个人标签 ───────────────────────┤
│ 电竞·游戏  电影  美食  阅读 …      │
├─────────────────────────────────┤
│           [ 关注 ]                │
└─────────────────────────────────┘
```

- 身份 1 显示「学院 · 专业」，身份 2 显示「学院 · 组织名」，跟官方一致
- 「参加活动」可点，进 [参加的活动列表](#参加的活动列表)；「加入组织」「广场动态」仍不可点——
  对应的两张列表页还没做，挂死箭头比不挂更糟
- `hours`（学时）接口里给了，官方页面没摆，这里也不摆；数据层已经解析好（`PersonProfile.hours`），
  以后要展示不用再改解析
- 标签为空时写「没有添加标签」，不用感叹号也不用插画
- 顶部不做头像模糊背景：官方那一层是 `blur` 组件，纯装饰，花里胡哨

## 关注

- 自己看自己不显示按钮（`id == 我自己的 userId`）
- 未关注 → 实心「关注」；已关注 → 描边「已关注，点击取消」
- 点完重新拉一次数据，用服务端返回的 `isFollow` 为准，不做本地乐观更新——关注状态跨设备一致更重要
- 失败只回滚状态并提示，不弹「操作失败」对话框

## 参加的活动列表

官方 `#/myAcitive/:id/:name`，接口 `GET activity/other-list`（`pageNum`/`pageSize`/`userId`）。

- 顶部写「共 N 次」，下面是活动行：封面、标题、时间 · 学时 · 分类
- 分页 10 条一页，翻页听「预加载下一页」；行点进去是活动详情（走现成的那套覆盖层）
- 官方那一页还有分类 / 排序两个 tab，但它的 `changeClassify` / `changeSort` **没有把参数发给接口**
  ——`activity/other-list` 只认分页和 `userId`。所以这里不做假筛选
- 行样式是公共组件 `ui/ActivityRow.kt`，组织详情的主办活动也用它

## 数据

接口与字段见 [api 文档](../api/win-9xueqi-api.md) 的「人物主页」一节。
命名注意：`data` 包里已经有 `UserProfile`（登录后自己的资料），别和这里混用；
本页的模型叫 `PersonProfile`。
