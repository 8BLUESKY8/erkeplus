# 人物主页

对应官方 `#/userShows/<id>`。只读为主，唯一的写操作是关注 / 取关。

## 入口

- 现在只有调试入口：`am start ... --es probe user_page --el user_id 1908337`
- 正式入口还没接：排行榜条目、组织负责人、组织成员列表里的头像都应该跳这里（见 [backlog](../plan/backlog.md) 第 2 条）

## 版式

```
┌ 返回  姓名 ──────────────────────┐
│ (头像 72dp)  姓名 [男]            │
│              学院 · 专业           │
├ 概况 ───────────────────────────┤
│ 参加活动   共 N 次                │
│ 加入组织   共 N 个                │
│ 广场动态   共 N 个                │
├ 个人标签 ───────────────────────┤
│ 电竞·游戏  电影  美食  阅读 …      │
├─────────────────────────────────┤
│           [ 关注 ]                │
└─────────────────────────────────┘
```

- 身份 1 显示「学院 · 专业」，身份 2 显示「学院 · 组织名」，跟官方一致
- 三个计数**不可点**：官方点进去是「参加的活动 / 加入的组织 / 广场动态」三张列表页，客户端都还没有，
  挂一个点了没反应的箭头比不挂更糟。等列表页做出来再开
- `hours`（学时）接口里给了，官方页面没摆，这里也不摆——别人的学时属于「官方没公开」的信息，
  不主动扩大暴露面
- 标签为空时写「没有添加标签」，不用感叹号也不用插画

## 关注

- 自己看自己不显示按钮（`id == 我自己的 userId`）
- 未关注 → 实心「关注」；已关注 → 描边「已关注，点击取消」
- 点完重新拉一次数据，用服务端返回的 `isFollow` 为准，不做本地乐观更新——关注状态跨设备一致更重要
- 失败只回滚状态并提示，不弹「操作失败」对话框

接口与字段见 [api 文档](../api/win-9xueqi-api.md) 的「人物主页」一节。

本页的模型叫 `PersonProfile`。
