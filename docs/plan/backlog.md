# 待办

## 1. 已报名的活动不该被屏蔽词吃掉

**现象**：已报名的活动也会被「内容屏蔽」过滤掉。用户报名之后回到列表，自己报的活动被关键词藏了。

**期望**：已报名的活动**默认不应用屏蔽词**；用户可以自己选要不要对它们也生效（默认关）。

**要点**：

- 默认不应用，需要一个开关（设置 → 内容屏蔽里）：「已报名的活动也应用屏蔽词」，默认关闭
- 判定依据是活动列表项里本人的报名状态（`applyStatus` / `identity` 一类字段，以实测为准），
  不是「已报名」筛选 tab——从其它 tab 进来时同样要认出这条
- 屏蔽计数（列表顶部「屏蔽规则隐藏了 N 条」）要跟着算法走，别把没被隐藏的算进去
- 影响范围：发现页列表、搜索匹配、排行榜里点进来的列表（如果走同一套过滤）

**状态**：已完成（2026-10-25）。实现：`BlockRules.blocks(item, blockEnrolledToo)`，
报名状态取 `applyStatus`（1 待审核 / 2 已通过），开关在「设置 → 内容屏蔽」，默认关闭。

## 2. 人物卡片点进人物详情

**现象**：排行榜顶部的前三名、组织页的负责人、成员列表里的头像，都只是一张图，点了没反应。

**期望**：参数够的时候点开人物详情。排行榜条目带 `userId`（要核实字段名），组织成员带 `id`，
两者应该都能直接跳。

**要点**：

- 依赖待办 3（人物详情页）；页面没有之前，不要先做半截的跳转
- 参数不够时（比如只有名字没有 id）保持不可点，不要跳到一个空页面

**状态**：待做（2026-10-25 记录）

## 3. 人物详情页

**现状**：官方页面 `#/userShows/<id>`（样本：<https://win.9xueqi.com/#/userShows/1908337>），
客户端完全没有对应页面。

**要做**：

- 先探接口：这个页面的数据从哪来（大概率和 `my-info`、`rank` 同族），字段是什么
- 页面内容按官方还原：头像、姓名、学院/专业/班级、学时学分、诚信值、可能还有公开的活动记录
- 隐私边界要想清楚：别人能看到什么，官方怎么控制可见性，客户端不能多拿

**状态**：已完成（2026-10-25）。接口 `message/chat/follow/user/info`，页面 `UserProfileScreen`，
字段说明见 [docs/design/person.md](../design/person.md)。只剩「卡片跳转」没接，见第 2 条。
